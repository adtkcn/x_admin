# 邮件发送

后端邮件能力集中在 `util/email.go`（基础发送）与 `util/email_code.go`（验证码场景），支持多账号、SSL、HTML/附件，并通过异步队列实现验证码与通知邮件补推。

## 一、基础发送（util/email.go）

### 配置

环境变量（`.env.yaml` 的 `Email` 段，数组）支持**多个账号**，发送时随机挑选以分摊限流：

```yaml
Email:
  - { Host: smtp.example.com, Port: 465, SSL: true, Username: u1, Password: p1, Timeout: 10 }
  - { Host: smtp.example.com, Port: 465, SSL: true, Username: u2, Password: p2, Timeout: 10 }
```

> 字段对应 `config.EmailConfigStruct`：`Host / Port / SSL / Username / Password / Timeout`。发件人直接使用 `Username`（无独立 From 字段）。

### 核心 API

```go
// util/email.go
var EmailUtil = &emailUtil{}

type EmailOptions struct {
    To          []string            // 收件人邮箱列表
    Cc          []string            // 抄送
    Bcc         []string            // 密送
    Subject     string              // 邮件主题
    HTMLBody    string              // HTML 正文（优先，若为空则用 TextBody）
    TextBody    string              // 纯文本正文
    Attachments []map[string]string // 本地附件文件路径列表，每项含 path / filename
}

func (e *emailUtil) GetEmailConfig(opts EmailOptions) (config.EmailConfigStruct, error) // 从 config.Config.Email 随机取一个账号
func (e *emailUtil) SendEmail(opts EmailOptions) error                                  // 发送邮件的统一入口
```

- 多账号：`SendEmail` 内部通过 `GetEmailConfig` 从 `config.Config.Email` 随机取一个账号发送。
- SSL：根据账号 `ssl` 字段决定是否 `mail.WithSSL()`；默认超时 10 秒（`sendEmail.Timeout`，<=0 时取 10）。
- 正文：优先 `HTMLBody`，为空时回退 `TextBody`，两者皆空则报错。
- 失败仅返回 error，不重试；重试/补推逻辑由调用方实现（如通知补推）。

## 二、邮箱验证码（util/email_code.go）

面向「注册/找回密码/绑定解绑」等需要验证码的场景，内置 Redis 存储与限频。实例为 `util.EmailCodeUtil`。

### 核心 API

```go
var EmailCodeUtil = &emailCodeUtil{}

// 发送验证码：scene 见下方场景常量，uid 可选（非空时绑定到具体账号，防止跨账号滥用）
func (e *emailCodeUtil) SendCode(email, scene, uid string) error
// 校验验证码（成功后删除，一次性）
func (e *emailCodeUtil) VerifyCode(email, scene, code, uid string) error
```

场景常量（`util/email_code.go`）：

```go
const (
    CodeSceneRegister = "register" // 注册账号
    CodeSceneReset    = "reset"    // 重置密码
    CodeSceneBind     = "bind"     // 绑定邮箱
    CodeSceneUnbind   = "unbind"   // 解绑手机
)
```

### 流程

1. **频率限制**：同邮箱 **60 秒内只能发送一次**（`user:code:limit:{email}`，60s TTL）；**每日上限 10 次**（`user:code:daily:{email}:{date}`，24h TTL）。
2. **生成与存储**：生成 6 位验证码（`ToolsUtil.Random(100000, 999999)`），写入 Redis（key 含 scene/email/uid），有效期 **5 分钟**。
3. **异步发送**：构造 `EmailCodeTask`（含 `To/CreatedAt/Subject/HTMLBody`），投递到队列 `email:code:send`（`util.QueueEmailCode = "email:code:send"`），由 worker 异步发送；**入队超过 60 秒的任务自动丢弃**（验证码有时效性）。
4. **校验**：`VerifyCode` 比对 Redis 中的验证码，成功后删除（一次性）。

### 关键常量/Key

```go
const QueueEmailCode = "email:code:send" // 队列名（util/email_code.go）

// Redis key 模板
codeLimitTpl = "user:code:limit:%s"      // 60s 频率限制
codeDailyTpl = "user:code:daily:%s:%s"   // 每日上限（含日期）
// 验证码存储 key：user:code:{scene}:{email}（uid 非空时插入 :{uid}）
```

## 三、通知邮件补推（notice_service）

系统通知可同时以邮件形式补推，由定时任务 + 异步队列保障可靠投递：

- 通知创建时若勾选邮件，`notice_service` 将任务投递到队列 `notice_email`（`notice_service.QueueNoticeEmail`）。
- worker 消费后调用 `util.EmailUtil.SendEmail`；无论成功失败都**回写最终状态**（`2` 成功 / `3` 失败）到通知记录，避免队列无限重试。
- 另有一条**每分钟**的固定定时任务扫描「待发送」通知并补推，作为兜底。

## 四、扩展：新增邮件场景

- **简单发送**：直接 `util.EmailUtil.SendEmail(util.EmailOptions{...})`。
- **需限频/异步**：仿照验证码，定义 payload + 队列名，投递到 `core.Queue`，并在 `app/queue/start.go` 注册消费者。
- **需状态追踪**：仿照通知补推，在业务表记录发送状态，由队列 worker 回写。

## 五、依赖与配置

- 依赖 SMTP 账号配置（`config/email.go`）。
- 验证码/限频依赖 Redis（`config/redis.go`）。
- 异步发送依赖队列与 Redis 后端（见 [异步队列](./异步队列.md)）。
