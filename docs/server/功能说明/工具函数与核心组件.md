# 工具函数与核心组件

本文汇总后端可被各业务复用「基础/扩展能力」：`util/` 工具包、`core/` 核心组件、存储引擎与通用控制器。这些是二次开发时最常被调用的基础设施。

## 一、util 工具包

| 文件 | 能力 |

| `tools.go` | 通用工具：UUIDv7、MD5、随机字符串、JSON 序列化、文件大小格式化等 |
| `verify.go` | 校验工具：手机号/邮箱/身份证等格式校验 |
| `string.go` | 字符串处理：截取、脱敏、驼峰转换等 |
| `array.go` | 数组/切片处理：去重、交集、包含判断等 |
| `cache.go` | 进程内缓存操作封装 |
| `redis.go` | Redis 封装：`Set/Get/HSet/HGet/LPush/BRPop` 等常用操作 |
| `redis_lock.go` | Redis 分布式锁：`NewRedisLock(key, expire)` + `Lock()/Unlock()`，用于定时任务/防并发 |
| `jwt.go` | JWT 生成/解析/刷新（后台 Token 与 C 端 JWT） |
| `email.go` / `email_code.go` | 邮件发送 / 邮箱验证码（详见 [邮件发送](./邮件发送.md)） |
| `sms_code.go` | 短信验证码（Redis 存储+限频，TODO 对接服务商） |

| `url.go` | URL 处理：相对路径转绝对路径 |

| `null_time.go` | GORM Null 时间类型工具 |
| `convert_util/` | 结构体字段拷贝（类型转换） |
| `excel2/` | Excel 导入导出（见 `导入导出excel.md`） |
| `img_util/` | 图片处理：缩放、水印、缩略图 |
| `aj-captcha-go/` | 行为验证码实现（滑块/点选） |

### 典型用法

```go
// 生成 UUID v7（util/tools.go）
id := util.ToolsUtil.MakeUuidV7()

// 邮件发送（util/email.go，var EmailUtil = &emailUtil{}）
util.EmailUtil.SendEmail(util.EmailOptions{ To: []string{"a@b.com"}, Subject: "标题", HTMLBody: "<p>内容</p>" })

// Redis 分布式锁（util/redis_lock.go）
lock := util.NewRedisLock("key", time.Duration(10)*time.Second)
if lock.Lock() {
    defer lock.Unlock()
    // 临界区
}
```

## 二、core 核心组件

| 模块 | 文件 | 说明 |
| --- | --- | --- |
| 数据库 | `core/db.go` | GORM 初始化，返回 `*gorm.DB`（全局 `core.DB`） |
| Redis | `core/redis.go` | Redis 客户端初始化（全局 `core.Redis`） |
| 日志 | `core/logger.go` | Zap 日志初始化（全局 `core.Logger`），支持分级、文件切割 |
| 请求 | `core/request/common.go` | 分页请求 `PageReq`（`Page/PageSize/Order/Sort` 等） |
| 响应 | `core/response/` | 统一响应：`Ok/Fail/FailWithResp`，错误码 `RespType` |
| 路由 | `core/` + `routes/` | Gin 引擎与路由注册 |
| WebSocket | `core/ws/` | 实时连接管理（见下文） |
| 事件总线 | `core/pubsub/` | mitt 风格 Pub/Sub（见下文） |
| 异步队列 | `core/queue/` | 工作队列（见 [异步队列](./异步队列.md)） |

### 统一响应

位于 `core/response`：

```go
// core/response/common.go
func Ok(c *gin.Context, data ...any)                  // 成功（data 可选）
func Fail(c *gin.Context, msg string)                // 失败（msg）
func FailWithResp(c *gin.Context, resp RespType)     // 失败（带 RespType）
func Send(c *gin.Context, code int, msg string, data any)

// 分页响应结构（非函数）
type PageResp struct {
    Count    int64 `json:"count"`    // 总数
    PageNo   int   `json:"pageNo"`   // 当前页码
    PageSize int   `json:"pageSize"` // 每页数量
    Lists    any   `json:"lists"`    // 数据列表
}
```

> 源码中分页数据由业务层自行组装 `PageResp` 结构后通过 `response.Ok(c, pageResp)` 返回，没有 `PageResp()` 函数。

示例：

```go
response.Ok(c)                            // 成功无数据
response.Ok(c, data)                      // 成功带数据
response.Fail(c, "参数错误")              // 失败带消息
```

## 三、存储引擎（plugin/storage）

文件上传采用驱动工厂模式，统一 `StorageEngine` 接口：

```go
// plugin/storage/storage_interface.go
type StorageEngine interface {
    PutObject(key string, data io.Reader, size int64) (string, error)
    ObjectExists(key string) (bool, error)          // 秒传判断
    GetObjectURL(key string) (string, error)
    // 分片上传
    InitMultipartUpload(key string) (string, error)
    UploadPart(key, uploadId string, partNumber int, data io.Reader, size int64) (string, error)
    CompleteMultipartUpload(key, uploadId string, parts []MultipartPart) (string, error)
    AbortMultipartUpload(key, uploadId string) error
    ListParts(key, uploadId string) ([]MultipartPart, error)
}
```

- **实现**：`storage_local.go`（本地磁盘）、`storage_oss.go`（阿里云 OSS，S3 兼容）。
- **引擎构造**：`GetStorageEngine()` 固定返回本地。
- **顶层上传**：`storage.StorageDriver.Upload(file)`（当前引擎写死 local，保存路径 `年月日/时/分/{uuid}.{ext}`）。
- **秒传**：`ObjectExists(key)` 判断对象是否存在。
- **分片清理**：`storage.CleanChunkTmpDir()` 由定时任务每整点调用，删除超过 `ChunkExpireHour` 小时（默认 24）的临时分片目录。
- **存储路径**：本地与 OSS 均使用 `{ext}/YYYYMMDD/HH/mm/{uuid}.{ext}` 结构，访问前缀 `/api/uploads`（由 `routes/api.go` 静态映射）。

> 详解见 [存储引擎](./存储引擎.md)。

## 五、通用控制器

位置：`app/controller/admin_ctl/common_controller/`

| 控制器 | 功能 |
| --- | --- |
| `upload.go` | 文件上传（本地/OSS 驱动 + 秒传） |
| `s3_upload.go` | S3 风格分片直传（初始化/上传分片/完成/列举/中止） |
| `album.go` | 相册分组与图片素材管理 |
| `captcha.go` | 行为验证码（获取/校验，aj-captcha） |
| `ge_tui.go` | 个推移动推送（对接个推 `PushToSingleBatchCID`，批量按 CID 推送） |
| `index.go` | 后台首页统计 |

> `ws.go`（路由层）为 WebSocket 升级处理器，对接 `core/ws.Manager`。

以上能力均可在新业务模块中直接复用，无需重复实现。
