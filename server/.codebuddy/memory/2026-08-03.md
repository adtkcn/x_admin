## 监控 schema 补 form tag（请求类结构体）
- 用户确认：走 `VerifyQuery`（`c.ShouldBindQuery`）的请求结构体不能只用 `json` tag，必须补 `form` tag。
- 已给以下走 query 的 `*Req` 结构体加 `form:"xxx"`（值与 json 一致）：
  - `MonitorClientListReq`/`DetailReq`/`DelReq`/`DelBatchReq`/`ErrorUsersReq`/`ExportReq`
  - `MonitorProjectListReq`/`DetailReq`/`DelReq`/`DelBatchReq`/`ExportReq`
  - `MonitorErrorListReq`/`DetailReq`/`DelReq`/`DelBatchReq`/`ExportReq`
- **不加 form tag 的结构体**：
  - 走 `VerifyJSON`（JSON body）的 Add/Edit 类：`MonitorClientAddReq`/`EditReq`、`MonitorProjectAddReq`/`EditReq`、`MonitorErrorAddReq`/`EditReq`（仅靠 json tag）。
  - 响应类 `Resp`/`ListResp`（仅 json）。
  - `MonitorErrorListAddReq`（controller 内直接构造，不绑定 HTTP，仅 json）。
  - `MonitorClientImportReq`/`MonitorProjectImportReq`/`MonitorErrorImportReq` 已有 `form:"file"`。
- 依据：`VerifyQuery` 用 `c.ShouldBindQuery`，只读 `form` tag/字段名，不读 `json`，原仅 json tag 会导致自定义查询条件（project_key 等）绑定失败。
- 验证：`go build ./...` 通过；`swag init` 重新生成成功；monitor 模块 swagger 字段全下划线（剩余 pageNo/pageSize 为 swag query 参数名规范化，createTime/updateTime 属 generator 模块，均非 monitor）。
- 注意：swag 会把 `page_no` query 参数在文档里显示为 `pageNo`（首字母大写），是 swag 已知行为，不影响实际绑定。
